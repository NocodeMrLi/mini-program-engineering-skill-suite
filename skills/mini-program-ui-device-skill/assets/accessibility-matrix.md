# 无障碍验证矩阵

| 维度 | 静态检查 | 设备/读屏检查 | 证据与失败表现 |
| --- | --- | --- | --- |
| ARIA 与语义 | 非原生交互元素具有正确角色、名称、状态；装饰内容不制造噪声 | 读屏名称、角色、状态与操作结果符合视觉语义 | 记录组件、状态、工具/系统版本与朗读结果 |
| 动态字体 | 不使用必然截断关键内容的固定高度；放大后布局有回流策略 | 系统字体级别变化后检查内容、按钮和错误提示 | 记录字体级别、机型、页面状态与截图/视频 |
| 对比度 | 文本、图标、状态和焦点指示不只靠颜色区分；采用项目批准阈值 | 真机在不同亮度/主题下复核可读性 | 记录计算工具/版本、色值来源和真机观察 |
| 触控热区 | 点击区覆盖可见目标且相邻操作不会误触；阈值来源明确 | 单手、边缘、安全区和连续操作实测 | 记录尺寸、设备、手势与误触结果 |
| 焦点顺序 | DOM/组件顺序与阅读、操作顺序一致；弹层有进入/退出策略 | 读屏或键盘能力可用时验证焦点顺序与返回位置 | 记录起点、完整顺序、陷阱和恢复位置 |

静态检查不能证明真机读屏、动态字体、触控或焦点体验通过；模拟器截图同样不能替代真机。缺少设备或辅助技术证据时，只报告静态层结果和 `unknown` 项，不隐瞒未执行层。
