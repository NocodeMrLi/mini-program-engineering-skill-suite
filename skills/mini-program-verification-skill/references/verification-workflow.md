# 小程序工程验证工作流与触发场景

## 充分性判断

验证强度由风险决定：共享状态、权限、数据写入、媒体、设备能力和发布配置需要更高层证据；纯文案或内部重构可在有依据时停在本地层。每项结论必须绑定同一版本指纹，旧截图和历史日志只能作为线索。

多页面、多流程或多状态项目先从路由、激活配置或代码事实源生成唯一目标单元，再分开统计所有目标共同的基础维度和有业务依据的专项维度。新增目标、重复 ID、金样漂移或无依据的 `N/A` 必须使只读 `check` 失败；更新基线本身不等于行为正确。

## 审计发现门禁

审计报告先把用户点名领域与确定性文件/目标清单做成覆盖表。每个领域必须落到“有发现、未发现或证据不足”，数量由同一工具清单计算并可回算；报告较长、发现较多或目录已经列出，都不能替代覆盖闭合。

先判定输入是完整工作区、可核验导出包还是部分快照，并记录来源、目标边界与完整性声明。若未证明完整，引用路径未包含只可标记为证据不足；不能据此声称真实仓库缺失、构建失败或发布阻断。只有可核验清单证明该路径本应位于完整边界，或绑定目标版本的实际构建或解析失败，才可把缺失升级为实现缺陷，并仍需按实际影响定级。

高严重度、关键错误和发布阻断结论必须先完成机制反证闭环：

1. 从调用点记录实际传入值，不只看被调函数的默认参数或孤立条件。
2. 按语言真实真值、类型转换和控制流求值，追踪会进入的分支与兜底。
3. 搜索能否定当前解释的早返回、默认值、缓存、异常捕获或后续覆盖。
4. 把已证明的代码缺陷与尚未证明的用户可见后果分开；后果链缺一环时降级或标记 `unknown`。

例如 JavaScript 的空对象和空数组仍为 truthy，不能把 `if (!value)` 当作会命中的分支；应继续追踪默认构造和后续写入。反证检查不是要求证明没有其他风险，而是防止用错误机理制造高严重度误报。

## 七层证据矩阵

| 层级 | 典型证据 | 不能推出 |
| --- | --- | --- |
| 静态检查 | 语法、类型、格式、配置、链接 | 运行行为正确 |
| 单元测试 | 独立逻辑与边界样本 | 模块协作正确 |
| 集成测试 | 页面、服务、接口或数据流 | 真机平台行为 |
| 状态矩阵 | 正常、空、错、边界、重复、恢复 | 设备和云端真实结果 |
| 真机验证 | 机型、系统、微信版本、步骤、截图/日志 | 云端部署或正式发布 |
| 云端验证 | 环境、版本、真实请求和平台日志 | 已上传或正式发布 |
| 发布验证 | 上传包、体验/审核/正式环境版本证据 | 用户正式验收 |

## 代表场景

### 场景 1：正常场景——功能实现后的回归验证

固定提交和构建指纹，运行静态、单元、集成与状态矩阵测试，保存退出码和失败明细。没有设备证据时最高只报告本地验证通过。

### 场景 2：正常场景——设备能力变更

权限、录音、相册、键盘或复杂手势变化需在代表性 iOS/Android 真机按明确步骤取证。模拟器结果单列，不能代替真机。

### 场景 3：边界场景——部分检查被环境阻塞

本地测试通过但设备、云端或平台凭证不可用。报告已执行层、阻塞原因、残余风险和所需最小授权，不把未执行项写成通过。

### 场景 4：失败场景——测试与目标版本不一致

发现构建产物、工具加载目录或测试分支不是目标版本时停止结果聚合，先恢复版本一致性；混合版本证据不能支持交付结论。

### 场景 5：不应触发——需求仍在讨论

用户尚未决定核心流程或成功条件。应进入产品规格而非用测试替代产品决定。

### 场景 6：失败场景——平均分掩盖关键退化

总体通过率达到阈值，但某个页面或流程出现关键正确性失败。矩阵必须按目标和维度暴露该失败并阻断对应结论，不能用其他目标的高分抵消。

## 下一项验证选择

按条件触发增量矩阵，不创建无关业务功能：

| 合同 | 必测反例 | 判定边界 |
| --- | --- | --- |
| [微信商品与云操作](../../../platforms/wechat/commerce-and-cloud-contracts.md) | 错格式/单位、伪造元数据、ACK 后失败、残留配置、重复/手动日志、订阅禁用或错目标 | 列表/受理/启用不证明到账/自然触发/业务完成 |
| [云状态与写入](../../mini-program-architecture-skill/references/cloud-state-and-write-contracts.md) | 本地完成外部失败、第二角色唯一冲突、暂停且诊断关闭、重编码或篡改、旧客户端 | 不重复本地提交，存量善后可发现，身份/幂等不放宽 |
| [页面恢复与预览](../../mini-program-implementation-skill/references/implementation-workflow.md) | 明确拒绝/未知、重进/晚到、闭交易普通启动、生产参数 | 实际页面/缓存及写入边界分别断言，展示页不等主流程 |
| [字段证据](evidence-admissibility.md) | 空尾注、缺独立字段、异单位、未知状态、历史未结 | 解析不标定未出现语义，合成映射不升正式 |
| [隐私版本与主体](../../../platforms/wechat/privacy-permission-matrix.md) | 修复页外权限、API/SDK、截断/旧附件、旧通过新处理 | 源码不决定平台分类，准备/上传/通过分列 |
| [工具与分工](../../mini-program-project-intake-skill/references/intake-workflow.md) | 两种工具链、旧产物/错误加载/混杂/手动/不在场/失败/冻结产物 | 不安装无关软件或追加无必要包，隔离不省必要质量门 |
| [阶段可达性](../../../references/routing-and-state-machine.md)及[资源测算合同](../../mini-program-release-skill/references/cloud-release-operations.md) | 入口依赖后续证据、无用量测算 | 拆入口/退出不拆高风险门，不捏造预测 |

同版本自然主流程已有证据先找缺口，异常演练优先局部故障注入与只读账证。异常测试不能自动新增历史展示、恢复入口或改变已验收产品语义。

原始场景、宿主作答、项目运行、成品非退化与真实平台证据各自报告；文档覆盖或确定性合同检查不是行为效果。评价工具成本须同质量、权限、证据边界并绑定实际操作/调用记录，不能用缩减验收换效率。新的 Skill 行为不能沿用旧签名发布证明。

在未覆盖项中优先选择能最大幅度改变当前结论、成本最低且无外部副作用的检查。若下一项需要外部写入或真实账号，先说明用途、风险和停止条件并取得授权。

验证计划同时维护必要质量门与用户可验收进展。每次新增检查点名改动/风险/失败或证据缺口，标出已合格可复用项；没有新信息不重跑整套。主项目普通路径已可安全接入时优先验证并交付该增量，隔离测试不能持续代替实际效果；仍未接入则报告具体阻塞与接回条件。测试数量增加但用户路径未推进，不能报告验收进度提高。
