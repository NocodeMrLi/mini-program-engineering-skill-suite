# 分维度质量覆盖合同

## 目标单元

从当前路由、激活配置或代码事实源确定性枚举页面、流程、状态或平台目标。每个目标必须有稳定 ID 且只出现一次；无法自动发现的目标说明来源和人工补录理由，不挑选有利样本。

## 基础与专项维度

- 基础维度：所有目标共同要求，例如可达、可渲染、没有未处理错误。
- 专项维度：仅在有业务依据时启用，例如状态迁移、权限、并发、恢复、跨设备、无障碍、设备、云端或发布。
- `N/A`：必须记录不适用依据；没有实现且本应适用的能力记为未覆盖，不得改成 `N/A`。

矩阵分别报告目标总数、基础通过数、每个专项的适用/通过/失败数、未覆盖项和 `N/A` 理由。一个总通过率不能掩盖单目标关键失败。

## 确定性基线

固定输入、目标发现规则和金样格式，提供两种动作：

- `generate`：显式生成候选基线，差异进入代码审查。
- `check`：只比较，不改文件；目标增删、重复 ID、实现漂移或金样变化均失败。

更新基线只代表接受新快照，不代表变化正确。机器金样、真机、云端和正式环境证据分层记录，互不替代。

## 最小负例

- 新增路由但矩阵无目标。
- 同一目标重复出现。
- 删除目标以提高通过率。
- 专项失败被平均分掩盖。
- 无依据把未实现维度标成 `N/A`。
- `check` 在漂移时自动重写基线。
