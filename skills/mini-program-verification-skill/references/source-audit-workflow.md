# 只读源码审计模式

适用：用户要对已有小程序做只读的产品/工程审计，不要求执行测试、修复或正式发布判定。此时用本页的短路径保留宿主 Agent 的源码推理能力；不要一次注入项目接管、平台、发布等所有阶段手册。始终遵守只读、敏感信息脱敏、证据状态不越级及外部动作逐项授权；若任务转为执行测试或发布签署，再按路由加载对应 Skill。

跨规格、架构、实现或设备领域的问题也先用本页；按当前缺口补读相关合同的小节，保留已有决定和源码核对，不整份拼接各阶段工作流。额外材料必须帮助当前判断，不能挤掉实际表达式、反例与结果的核算；同样的范围、证据与质量门保持。

1. 先运行套件的只读 `scripts/audit_source_inventory.py <项目根目录>`。其 `file_count`、`files`、`tree_sha256`、`git_commit` 是报告的版本基线；`git_commit=unknown` 时不得引用外层仓库提交。无法运行时，文件数量和提交号都写 `unknown`，不声称“已读全部文件”。`review_targets` 只列通用源码构造及行号，不是漏洞结论；`review_challenges` 是待求值的问题，不是预设答案；`hotspot_scan_skipped` 不得冒充已核验。
2. 先按用户点名领域追踪主流程：入口动作→写入→后续读取→状态转换→页面呈现，覆盖继续操作、离开再返回和重进。持久化存在不等于呈现消费了它；同一业务状态在页面、分享或导出等实际输出之间也要核对一致性。每个领域先给有发现/已检查无问题/证据不足及对应路径，再做热点边界台账；工具给出的 `review_targets` 不能替代或挤掉主流程覆盖。仅凭源码判断静态可达性。对定时器/监听/订阅等资源分别查创建、暂停、恢复、销毁，覆盖离开再返回。
3. 对“不重复”“追加不影响”“自动恢复”等全称承诺，用实际表达式和最小边界输入求反例；必须算出实际结果，不能用省略号代替。一个反例只能推翻全称承诺，不能反过来声称每个输入都失败；不能把“以后补测试”代替本次源码核验。
4. 每个高严重度发现写调用路径、条件求值、实际分支和可观察后果，再搜索反证。优先处理当前用户路径可触发的问题；只在未来扩容、异常注入或尚未建立的条件下出现的边界风险，不凭风险名称升为当前发布阻断。区别已声明的产品契约与审计者希望增加的体验，后者只能列为建议，不得擅自升为缺陷。数值运算、类型转换和 API 参数处理按实际运行时语义求值，不能由数值写法或函数名臆断结果；语义未核实就保留未知。平台规则、隐私配置及真机/上传/审核状态缺当前官方或运行证据时写 `unknown`，不得上升为已证实阻断。
5. 对 `review_targets` 的每个类别按 `review_challenges` 求一个最小反例或反证，并给出简短台账：实际路径/行号、输入或状态序列、实际表达式/分支结果、结论（发现/已检查无问题/证据不足）。数值类型检查要逐个代入 `NaN`、无穷、小数和越界值，不能把区间比较自动当作有限数校验。不能只抄类别名就宣称审完；同类多个路径或同文件多个行号要核对有无不同机制。最终以有证据的发现、修复选项、定向验证表为主；清单外路径、未运行的测试和未观察的环境单列为限制。不要为了覆盖术语而扩写无关建议。

用户或评测器已提供清单时，标明“所提供的清单”，不能声称本次亲自执行工具；目标/挑战为空时不虚构“工具要求”的数值检查。已提供的受控执行读回须保留初值、步骤和范围，并用于核对同条件下的静态轨迹；相冲突时先查覆盖与调用顺序，不把文字推演优先于已确认读回。一个给定初值的正例不能替其他对象形状或未测路径作证，仍不得升级为设备或生产证据。

输出发现和修复建议前，逐条做以下核对；不满足的因果结论改为证据缺口。修复本身也逐条回代产品契约：禁止的状态变化不能靠补写日志或提交持久化变得合规；保留已承诺的数据和操作，不要求用户重复已确认的产品决定。

- **对象与消费链**：列清谁写哪个对象、是否复制、谁实际读取。一个副本被修改不证明另一个页面的草稿也被修改；跨对象影响须有共享引用、回写或重读路径。名称/关系字段被持久化不等于目录实体已创建，仍须查实体登记及选择入口的读取链；已证实的字段副作用照常报告。
- **字段含义**：分别核对动作来源、原关系和当前入口条件。关系为空可能是合法的未归属状态，不能据此推断动作来源未知，也不能建议一律拒绝空关系恢复；确实缺来源或前态证据时才按已获准回退规则处理。
- **修复后的新输入**：建议同代保存复用或用返回快照刷新状态前，检查同对象、会话、代次及完整提交内容；字段变化未必递增代次。逐步代入“提交后、返回前又编辑”的顺序，旧返回不得整对象覆盖新草稿；只确认对应提交的结果，保留之后输入。只有版本号相同不足以证明内容相同。
- **异步顺序**：按调用和微任务顺序核对旧结果、切换对象、失败与重试；`async` 函数体无内部等待不代表调用方 `await` 没有让出。局部正例不能推导全部路径无竞态，修复建议也须经同样的反例检查。

提交报告前，可用 `python3 scripts/audit_source_inventory.py <项目根目录> --report <报告文件> --check-challenges` 检查报告中的总文件数、提交号和已触发数值核验的 `NaN` 边界是否至少显式出现。词语出现不能证明计算或结论正确；仍须人工核对反例和独立产物评审。
