# 只读源码审计模式

适用：用户要对已有小程序做只读的产品/工程审计，不要求执行测试、修复或正式发布判定。此时用本页的短路径保留宿主 Agent 的源码推理能力；不要一次注入项目接管、平台、发布等所有阶段手册。始终遵守只读、敏感信息脱敏、证据状态不越级及外部动作逐项授权；若任务转为执行测试或发布签署，再按路由加载对应 Skill。

1. 先运行套件的只读 `scripts/audit_source_inventory.py <项目根目录>`。其 `file_count`、`files`、`tree_sha256`、`git_commit` 是报告的版本基线；`git_commit=unknown` 时不得引用外层仓库提交。无法运行时，文件数量和提交号都写 `unknown`，不声称“已读全部文件”。
2. 从实际入口沿用户操作追踪输入、读写、状态转换和输出；仅凭源码判断静态可达性。对定时器/监听/订阅等资源分别查创建、暂停、恢复、销毁，覆盖离开再返回。
3. 对“不重复”“追加不影响”“自动恢复”等全称承诺，用实际表达式和最小边界输入求反例；不能把“以后补测试”代替本次源码核验。
4. 每个高严重度发现写调用路径、条件求值、实际分支和可观察后果，再搜索反证。平台规则、隐私配置及真机/上传/审核状态缺当前官方或运行证据时写 `unknown`，不得上升为已证实阻断。
5. 最终以有证据的发现、修复选项、定向验证表为主；清单外路径、未运行的测试和未观察的环境单列为限制。不要为了覆盖术语而扩写无关建议。

提交报告前，可用 `python3 scripts/audit_source_inventory.py <项目根目录> --report <报告文件>` 检查报告中的总文件数和提交号。这个检查只能拦来源矛盾，不能证明缺陷分析正确；发布门禁仍须独立产物盲评。
