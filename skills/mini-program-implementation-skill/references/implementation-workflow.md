# 工程实现工作流与触发场景

## 实施检查表

- 基线包含规则、Git/文件状态、相关测试、生成关系与用户已有改动。
- 每个修改文件都能直接映射到用户目标；删除行为覆盖模板、样式、状态、计算和资源引用。
- 新行为或缺陷有先失败的测试/复现；测试期望独立于被测实现，不以源码关键词代替行为证据。
- 共享状态、接口或数据契约变化覆盖正常、空、错误、边界和重复操作。
- 源码、生成脚本、构建产物和平台状态没有混写；只报告实际执行到的验证层级。
- 云资产/批量导入按 manifest、executor、verifier、report 分离；长任务有界并发、进度与失败清单，部分远端数据按唯一键补齐。
- 会改变运行行为的派生资产使用候选版本、单一激活源、原子切换和可审计回滚，不直接覆盖当前激活版。

## 代表场景

### 场景 1：正常场景——按已确认规格增加局部功能

已有事实图、页面行为和验收标准。先固定允许修改文件与测试命令，写失败测试，再用最小代码实现；不得顺手重构相邻模块或增加未确认入口。

### 场景 2：正常场景——语义删除已有行为

用户明确不要某个提示。检查渲染、样式、状态、计算、事件和资源引用，删除整个语义链，并运行相邻状态回归；不能只用 CSS 隐藏。

### 场景 3：边界场景——工作区已有用户改动

目标文件存在未提交修改。先识别哪些属于用户、哪些属于本任务；能安全叠加时做最小补丁并逐块复核，无法区分时停止请求方向，不能回退或覆盖。

### 场景 4：失败场景——测试与事实源冲突

旧测试要求的行为与当前已确认规格相反。保留冲突并确定当前权威事实源；没有证据前不改测试来“变绿”，也不按旧测试改变产品语义。

### 场景 5：不应触发——只有症状没有根因

用户只说真机偶发白屏且没有稳定复现。应先进入调试流程建立证据链，而不是直接猜测文件并修改。

### 场景 6：边界场景——远端已有部分资产

先读远端数量、唯一键和分布基线，再按 manifest 幂等补齐缺失项；完整性复验通过前不写“资产交付完成”，不得清库后全量重传。

## 创建请求的客户端占位

调用创建接口前缓存请求标识的页面，结果按协议分为“已成功、明确未创建、结果未知”。无资源编号或用户取消界面不能推断远端未创建。

- 明确未创建：只释放对应本次请求的临时占位，显示真实拒绝原因；其他未结业务仍受原规则约束，不删除远端记录或自动重试。
- 结果未知：保留原请求标识，按已核查询/幂等合同恢复；重进或重复点击不能换键重建。
- 成功与晚到结果：缓存更新绑定当前请求/尝试；旧拒绝不能清掉新请求占位，旧成功不能覆盖新状态。

原创小程序测试调用实际页面方法及缓存边界，覆盖本地前置拒绝、服务端明确未创建、无编号超时、已创建丢响应、重进、重复点击和晚到；分别断言缓存、可继续操作和服务写入次数，不能只测服务返回码或源码关键词。

## 主项目正常预览交付

实施批次按 [质量、推进与及时反馈](../../mini-program-project-intake-skill/references/intake-workflow.md) 定义用户可验收增量、正常入口和必要质量门，优先消除实际效果交付阻塞；不能只累计内部测试而长期不给开发者可见结果。隔离演练有具体风险、待补断言和接回条件，无新增风险或改动时不重复已有合格验证。

准备好且可安全接入的功能及时进入主项目普通入口，开发者用现有工具普通编译、手机预览并反馈；用户选择手动编译时尊重分工。界面可见、测试身份、真实交易/写入与正式开放分别控制，不为显示入口打开生产交易总门，也不把未验真实交易当作无交易界面的一律阻塞。

沿普通启动到业务页、入口、弹窗核已获准操作，保留对应云写入/交易门禁；启动、进页、点击的账户写入、上传、扣额及收费调用必须逐项核。无付款不等于无副作用，目录隔离不证明云环境隔离。生产构建和预览参数不能误开受限入口；直接确认也应在实际写入边界受控。

独立展示页、隔离测试、模拟器、手机及用户验收分别报告；隐藏参数/特殊启动页不证明主流程可用。单功能包/二维码只用于明确隔离需要、尚不能安全接入或现有工具无法覆盖，记录接回主项目条件并复用有效产物。

## 验证交接

交给验证阶段的内容只包括目标、差异、保护项、执行证据、未覆盖层级、残余风险和回滚方式。实现报告不得使用 `accepted`、`device-verified`、`uploaded` 或 `released`，除非另有对应独立证据。
