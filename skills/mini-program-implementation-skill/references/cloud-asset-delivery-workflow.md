# 云资产、批量导入与派生资产交付工作流

## 四个独立证据面

批量上传或导入必须拆分为 manifest、executor、verifier、report 四个职责。它们可以是独立脚本，也可以是同一工具的独立子命令，但不能用 executor 的“成功返回”替代完整性验证或运行时接线证据。

### Manifest

每个目标记录逻辑 ID、来源、目标 key、大小、SHA-256、内容类型和所属批次；声明预期总数、允许 key 前缀和 manifest 自身指纹。目标 key 越界、逻辑 ID 重复或来源不可读时，在写入前失败。

### Executor

- 只从安全注入读取上传凭证，上传身份、运行时读取身份和部署管理身份按最小权限分离。
- 长任务持续输出已处理、成功、失败、剩余、最近对象和失败清单；并发必须有界。
- 以 manifest 为幂等输入；中断后先刷新远端事实，再只重试缺失或验证失败项。
- 导入远端已有数据时先取只读基线，按唯一键补齐，不清库重来。

### Verifier

- 原始对象完整性与业务访问接口分开验证。
- 对象检查至少核对状态码、大小、内容类型和摘要；`HEAD` 不可用时允许受控 `GET` 回退。
- 404、403、5xx、摘要不一致和业务接口拒绝分别报告。
- 数据导入后只读核对总数、唯一键、状态/分类分布和明显异常值。

### Report

报告绑定 manifest 指纹、目标环境、开始/结束时间、计数、失败项、验证结果和不可推出状态。状态至少拆分为本地生成、远端写入、完整性复验、运行时接线、真实页面/流程使用和用户验收。

## 写入前安全扫描

私有导入数据在离开本地边界前扫描绝对用户路径、凭证、明文兑换/恢复码、私有业务字段和越界 key。扫描结果只记录规则、位置和脱敏指纹，不回显命中值。资产数量、可检索或已导入都不能冒充运行时已使用或成品有增益。

## 可执行派生资产

题库索引、词典、审核规则、提示词包和离线配置等会改变运行行为的派生资产必须：

1. 候选写入独立版本，不覆盖当前激活源。
2. 通过 schema、来源清单、内容一致性、回归和人工审批后才可晋升。
3. 先写不可变历史与变更记录，再原子切换单一激活源。
4. 回滚同样记录版本、原因、批准和时间。
5. 在隔离目录完成一次“旧版 → 新版 → 旧版”演练，不触碰生产激活源。

## 停止条件

manifest 不完整、凭证边界不清、远端基线不可读、目标 key 越界、完整性无法复验或激活没有回滚目标时停止。不得用手工补一条记录、扩大忽略规则或重复全量写入来制造绿色结果。
