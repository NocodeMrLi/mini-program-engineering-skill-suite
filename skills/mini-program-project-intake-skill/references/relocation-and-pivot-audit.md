# 工作区重定位与产品转向审计

## 工作区身份组

接管、恢复或继续已有项目时，先交叉验证以下字段，不沿用旧会话中的路径或名称：

| 字段 | 最低证据 | 失败口径 |
| --- | --- | --- |
| 实际项目根目录 | 当前可读目录与项目入口 | `unknown`，继续只读发现 |
| Git 顶层目录 | `git rev-parse --show-toplevel` 或明确非 Git 项目 | 不把子目录当项目根 |
| 规范化远端 | 远端名称与脱敏 URL/仓库身份 | 不用旧仓库名补值 |
| 当前分支与 HEAD | 分支名、提交 SHA、工作区状态 | detached/无 Git 时如实记录 |
| 当前执行文档 | 从仓库内重新发现的入口文档 | 旧文档仅作历史线索 |
| 构建/工具加载目标 | 当前配置或工具可见路径 | 没证据时保持 `unknown` |

用户给出的路径、项目名、远端名、默认分支或文档名失效时，从已确认的可信父目录按目录结构、Git 身份和项目配置重新发现。找到同名目录不等于找到目标项目；至少用两个独立身份字段交叉确认。

## 产品转向五向基线

收费对象、用户边界、核心交付方式、平台路线或产品定位发生实质变化时，在继续功能开发前核对：

1. 代码：默认路由、权限、接口和开关是否仍执行旧定位。
2. 资产与数据：旧目录、元数据、兼容字段和远端数据是否被误当成新规则。
3. 远端提交：本地/远端 SHA、分支和未提交修改是否与审计对象一致。
4. 正式文档：当前事实源、README、任务入口和部署说明是否同口径；历史文档须显式标历史。
5. 云端与发布：配置、导入、部署、真实请求、平台上传和用户验收分别有什么证据。

旧实现可以为了兼容或未来复用而保留，但必须退出新的默认用户路径。文档更新不能替代运行行为、云端状态或发布证据。

## 停止条件

身份组无法唯一定位项目、五向事实互相冲突，或继续开发会把旧定位重新带回默认路径时，停止在只读审计。输出冲突、已验证字段、`unknown` 字段和下一项最小辨别动作。
