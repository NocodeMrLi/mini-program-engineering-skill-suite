## 根目录与规则

确认用户给出的目录真实存在，并从项目根向当前工作目录查找 `AGENTS.md`、`CLAUDE.md`、README、包管理和平台配置。规则文件决定可用命令、文档边界和验证方式，必须先于一般经验。路径、项目名、远端名、默认分支或文档入口失效时，按 [工作区重定位与产品转向审计](relocation-and-pivot-audit.md) 从可信父目录重新发现，并用项目配置与 Git 身份交叉确认；不要沿用旧路径猜测当前项目。

## 目录画像

优先使用 `rg --files`，保留确定性文件清单和总数，再按文件名定位页面入口、路由、组件、状态、API、云函数、测试、构建与平台配置。分类统计必须能回算到同一清单；不要按“页面数 × 常见文件数”手算总量，也不要把“清单中存在”写成“已逐文件审查”。目录画像只回答“目前有什么”，不评价功能已经可用。

## 事实分类

把发现分为四类：

- 当前事实：直接由源码、配置、版本控制或本轮平台返回证明。
- 历史记录：解释此前意图，但需要当前证据确认是否仍有效。
- 推断：由多个事实合理推出，必须标注推断依据。
- 未知项：证据不足，且可能影响范围、架构、验证或发布。

当文档与源码冲突时同时保留两者，并说明当前应采用哪个事实源以及为什么。

## 风险与边界

至少检查工作区未提交改动、生成目录与源码混淆、多个状态源、测试或构建命令缺失、外部服务、权限、隐私、平台配置和过期文档。产品定位发生实质变化时增加代码、资产/数据、远端提交、正式文档、云端/发布五向基线。改动边界应写成具体文件、模块与行为，不用“相关部分”之类模糊措辞。

## 输出质量

涉及编译、预览或交付时，先核当前源/产物/加载工程、已有工具和用户分工，判断缺的是源码修复、编译刷新、工具故障还是远端上传。启动到点击的副作用独立核验，目录隔离不证明数据隔离。

简单原生动作由助手准备准确对象、动作、预期结果及失败回报，用户已选择手动时不接管 GUI、重复导入或追加无必要包；用户不在场继续独立工作。混有未验收改动时必须隔离范围，优先已有正确来源；隔离来源、采用工具、谁编译分别决策。有效冻结产物复用，新编译重核身份与范围。

文件优先指定路径和已有正式执行记录。仅下一步直接上传/填写、原路径难找且确实减负的重要材料才考虑醒目副本，不能统一放桌面；核有效稿、同源及替代关系，不恢复已收起副本。远程交付需可用附件/链接，敏感证据不得为方便公开复制。普通进度在聊天，必要计划/证据按原项目约定归档，不额外造明日进度或未请求的交接文件。

同质量、授权与证据边界下比较操作数、寻找/切换负担、等待、调用/token 和外部请求成本；没有改善则缩小路由或用原生流程，不强加套件步骤。未取实际结果不能宣称短路径成功或量化效率提高。

## 质量、推进与及时反馈

质量是核心底线：已确认的产品语义、正确性、安全、存量不变量和必要证据不能为速度让步。效率与用户可见进展同时进入计划，不以内部测试数量或方案篇幅代替交付。

- 每个实施批次用短记录明确用户可验收增量：“本批用户能看到/操作/验收什么、所在工程及普通入口、必要质量门、反馈方式”。没有界面的任务给可检查的数据、接口结果或文件，不凭空增加 UI；沿用已有执行文档，不为此另造进度文件。
- 能安全接入的功能及时进入主项目正常路径，便于开发者用已有工具普通编译、预览并反馈；真实交易/外部写入未获准时保留相应关闭门，不把它当作安全界面展示的统一阻塞。
- 隔离只解决具体风险，写明当前不能接入的原因、待补断言、最小演练及接回条件。用户尚看不到实际效果时，优先排除主入口接入阻塞，不无限追加隔离演练。
- 测试或推演前点名它解决的新增改动、风险、失败或证据缺口；已有同范围同版本合格证据复用。重复检查无新信息就停止，保留必要门禁；禁止以“更全面”为由反复全量回归、做新包或重复同一推演。
- 汇报先说明新增可验收结果、质量是否守住、阶段退出还缺什么、下一步与必要用户配合，再列证据。源码接入、工具可见、手机验证、用户反馈分别取证；承诺了反馈路径却未取结果时明确未完成，不自称主项目效果已交付。

输出必须让后续智能体无需重新猜测即可回答：项目是什么、当前目标是什么、哪些事实可信、哪些内容不能碰、还有什么不知道、进入下一阶段前缺什么。用户点名多个审计领域时，逐项标记“有发现 / 未发现 / 证据不足”，并把证据不足保留为未知项；不能用篇幅或发现数量冒充领域已覆盖。接管报告不宣布代码、真机、云端、上传、验收或发布成功。
