# 项目接管方法

## 目录

1. 根目录与规则
2. 目录画像
3. 事实分类
4. 风险与边界
5. 输出质量

## 根目录与规则

确认用户给出的目录真实存在，并从项目根向当前工作目录查找 `AGENTS.md`、`CLAUDE.md`、README、包管理和平台配置。规则文件决定可用命令、文档边界和验证方式，必须先于一般经验。

## 目录画像

优先使用 `rg --files`，再按文件名定位页面入口、路由、组件、状态、API、云函数、测试、构建与平台配置。目录画像只回答“目前有什么”，不评价功能已经可用。

## 事实分类

把发现分为四类：

- 当前事实：直接由源码、配置、版本控制或本轮平台返回证明。
- 历史记录：解释此前意图，但需要当前证据确认是否仍有效。
- 推断：由多个事实合理推出，必须标注推断依据。
- 未知项：证据不足，且可能影响范围、架构、验证或发布。

当文档与源码冲突时同时保留两者，并说明当前应采用哪个事实源以及为什么。

## 风险与边界

至少检查工作区未提交改动、生成目录与源码混淆、多个状态源、测试或构建命令缺失、外部服务、权限、隐私、平台配置和过期文档。改动边界应写成具体文件、模块与行为，不用“相关部分”之类模糊措辞。

## 输出质量

输出必须让后续智能体无需重新猜测即可回答：项目是什么、当前目标是什么、哪些事实可信、哪些内容不能碰、还有什么不知道、进入下一阶段前缺什么。接管报告不宣布代码、真机、云端、上传、验收或发布成功。
