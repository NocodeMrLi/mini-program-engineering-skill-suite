# 微信平台证据层与触发场景

## 证据层

| 层级 | 能证明什么 | 不能自动证明什么 |
| --- | --- | --- |
| 源码 | 当前文件与配置内容 | 已构建、已加载或可运行 |
| 构建产物 | 某次构建生成的文件 | 与当前源码一致或开发者工具正在使用 |
| 开发者工具 | 工具本轮加载和模拟结果 | 真机、云端、体验版或正式环境结果 |
| 真机 | 特定设备、本轮版本的行为 | 所有设备或审核通过 |
| 云端/后台 | 特定环境本轮返回 | 客户端已接入正确环境 |
| 体验版 | 平台存在可体验版本 | 审核版或正式版已更新 |
| 审核版 | 已提交或平台返回审核状态 | 已正式发布 |
| 正式版 | 平台正式版本或生产结果 | 未覆盖功能都正确 |

## 代表场景

### 场景 1：正常场景——开发者工具加载目录异常

只读比较源码目录、构建输出和平台配置，说明工具实际加载哪一层；不通过清缓存或重建来掩盖证据缺口。

### 场景 2：正常场景——权限与隐私发布前核对

列出源码调用、声明和平台要求之间的映射。涉及当前政策或审核要求时，必须查微信官方当前资料并记录核验日期。

### 场景 3：边界场景——只有历史截图

截图可作为历史记录，但不能证明本轮配置、真机或平台状态。输出仍缺少的当前证据和安全的只读检查路径。

### 场景 4：失败场景——需要真实凭证或平台写操作

核对必须登录、上传或填写真实标识才能继续。应停止，说明需要的用户授权和风险，不索取或回显 Secret。

### 场景 5：不应触发——纯通用产品流程

用户只想确定目标用户、主流程和空状态，没有微信特有权限、工具或发布问题。应由产品规格 Skill 处理。

## 时效性判断

平台文档、权限、隐私、审核、接口可用性和工具行为都可能变化。提出确定性结论前优先查微信官方开发文档或平台当前返回；找不到一手证据时保留未知，不用博客或记忆替代官方事实。
