# 公开与内部文档边界

公开文档只记录可公开能力、使用条件、限制、匿名示例和通用安装信息。内部文档可以记录项目决策、部署证据、环境状态、回滚步骤和真实排障上下文。

## 决策规则

- 能帮助外部使用者正确调用 Skill，且不会识别具体项目的内容，可以公开。
- 只能证明某个项目当前状态的日志、提交、平台截图或云端结果，留在内部。
- 公开 README 或示例不得承载部署证据、后台状态或内部路径。
- 文档同步以任务需要为准，不为了显得完整而扩写无关内容。

## 小程序公开交付说明

- 面向外部的 README、项目主页、体验说明、二维码说明和宣传视频，应优先说明项目价值、适用对象、使用方法和明确边界，不把内部排障过程、临时绕路或客户端限制写成主内容。
- 小程序二维码、体验入口、说明视频、安装链接和演示素材需要区分“展示路径”和“稳定访问路径”：主要阅读环境应保持干净可信，手机端、扫码入口或 App 内浏览器也应有可继续访问的路径。
- 标题、链接文字、角标和说明中出现的时长、数量、版本、价格、配额等可验证数字，必须和当前素材、文件元数据、配置或事实源一致；不确定时使用模糊但真实的表达，不编造精确数字。
- 公开文案只描述用户自然动作，例如查看说明、扫码体验或安装调用；具体平台限制、失败原因和兼容取舍留在内部维护文档。
- 公开安装表、安装器 target、示例命令和真实 Agent 读取目录必须同源核对；不同运行器路径不同的，不要合并成一行表达，避免用户安装成功但运行器不可见。
- 若公开展示真实来源案例，必须说明它只用于解释方法来源或真实协作背景，不作为源码开放、项目验收、审核通过、正式发布或业务数据公开的证据。

## 最终检查

逐项核对项目身份、资源定位、开发者身份、环境访问、商业信息和未发布功能是否可能从文本组合中被还原。存在疑问时按内部信息处理。
